# Discord Audio Relay Bot
특정 디스코드 서버(길드) 전용으로 동작하는 오디오 릴레이 봇입니다.
길드원 누구나 본인 컴퓨터에서 재생 중인 오디오 소스(브라우저, 음악 스트리밍 앱 등) 하나를 선택해
지정된 음성 채널로 실시간 송출할 수 있습니다. 게임 중 노래를 공유하는 용도를 전제로 설계되었습니다.

> 비공개 프로젝트입니다. 공개 배포나 다른 서버에서의 사용을 목적으로 하지 않습니다.

## 개요
- 단일 길드에서만 동작
- 한 번에 한 명만 송출 가능 (선점 시 다른 사용자의 요청은 거부됨)
- 길드원은 봇 토큰 없이, 서버 주소만 들어 있는 배포용 실행 파일을 실행하고 디스코드 `/start`로 받은 일회용 접속 코드를 입력해 오디오 송출 ([보안](#보안) 참고)
- 오디오 캡처는 앱 단위(예: 브라우저 탭, 음악 앱)로 선택 가능 — 시스템 전체 소리가 아님

## 길드원용 사용법
개발자가 아니어도 아래만 하면 됩니다.

1. **실행 파일은 길드 디스코드 채널에서 받으세요.** `AudioRelayClientGui.exe` 하나뿐이고 설치는 필요 없습니다. 이 파일은 길드 밖으로 공유하지 마세요.
2. 디스코드에서 노래를 공유하고 싶은 음성 채널에 먼저 접속
3. 채팅창에 `/start` 입력 — 본인에게만 보이는 **6자리 접속 코드**가 나옵니다
4. 방금 받은 `AudioRelayClientGui.exe` 실행
5. 접속 코드를 입력하고, 목록에서 소리를 보낼 앱(브라우저, 음악 앱 등)을 선택한 뒤 **시작** 클릭
6. 끝낼 때는 디스코드에서 `/stop` 입력 (또는 그냥 음성 채널에서 나가도 자동 종료됨)

> 서버 주소는 입력할 필요가 없습니다 — 배포된 실행 파일에 들어 있습니다. 접속 코드는 10분 안에 한 번만 쓸 수 있습니다. 클라이언트를 다시 켜야 하거나 코드가 만료됐다면 `/start`를 한 번 더 입력하면 새 코드가 나옵니다.

## 아키텍처
```
[로컬 클라이언트 A] 오디오 캡처 → WebSocket 전송 ─┐
[로컬 클라이언트 B] 오디오 캡처 → WebSocket 전송 ─┼→ [중앙 릴레이 봇] → 디스코드 음성 채널
[로컬 클라이언트 ...]                              ─┘   (세션 잠금 관리)
```
- **로컬 클라이언트**: 각 사용자의 Windows PC에서 실행. 특정 프로세스의 오디오만 캡처해 중앙 봇으로 전송
- **중앙 릴레이 봇**: 클라우드에 24/7 상주. 디스코드 음성 채널에 접속해 있다가, 인증된 클라이언트가 보내는 오디오를 그대로 송출. 동시에 한 명만 송출 가능하도록 세션 상태 관리

## 기술 스택
| 컴포넌트 | 스택 |
|---|---|
| 중앙 릴레이 봇 | Node.js, discord.js, @discordjs/voice, ws |
| 로컬 클라이언트 | C# (.NET), Windows Process Loopback Capture API |
| 호스팅 | Oracle Cloud Always Free (AMD VM.Standard.E2.1.Micro) |
| 통신 | WebSocket (ws, 원시 PCM 전송), 봇에서 Opus 인코딩 후 디스코드로 송출 |

## 개발 로드맵
- [x] 1단계 — 봇이 음성 채널에서 로컬 테스트 파일 재생
- [x] 2단계 — 시스템 오디오 캡처 → 봇 재생 (로컬, 앱 분리 없이)
- [x] 3단계 — Process Loopback API로 특정 앱만 캡처
- [x] 4단계 — 클라이언트-봇 네트워크 분리 (WebSocket 계층)
- [x] 5단계 — 세션 잠금 + 인증 (사용자별 토큰은 만들었다가 제거, 공유 비밀키를 거쳐 일회용 접속 코드로 대체)
- [x] 6단계 — Oracle Cloud 배포 및 실사용 테스트

## 시작하기
> 봇을 직접 운영하거나 클라이언트를 빌드하는 관리자용 설정입니다. 길드원은 위 "길드원용 사용법"만 따르면 됩니다.

### 요구 사항
- Node.js 22 이상 (LTS 권장)
- .NET 9 SDK
- 디스코드 봇 토큰 (개발용 별도 애플리케이션 사용 권장)

### 환경 변수 설정 (bot)
`bot/.env`는 토큰 등 민감한 값을 담고 있어 git에 커밋되지 않습니다(`.gitignore`에 `.env` 규칙 있음).

```bash
cd bot
cp .env.example .env
```

이후 `bot/.env`를 열어 `DISCORD_TOKEN`, `GUILD_ID`, `WS_PORT` 등 값을 채워주세요.

### GUI 클라이언트 배포용 빌드 (관리자용)
`client-gui/secrets.local.json`(gitignore 대상, `secrets.local.json.example` 참고)에 실제 서버 주소(`serverUrl`)를 넣어두면 빌드 시 실행 파일에 내장됩니다. 비밀키는 넣지 않습니다. 인증은 `/start`로 받는 일회용 접속 코드로 합니다.

```bash
cd client-gui
dotnet publish -c Release -p:PublishProfile=win-x64
```

`bin/Release/net9.0-windows10.0.19041.0/publish/win-x64/AudioRelayClientGui.exe` 파일 하나만 생성되며, .NET 런타임 설치 없이 그 파일 하나로 실행됩니다. 이 파일에는 서버 주소가 들어 있으므로 GitHub Release 같은 공개된 곳에는 올리지 말고, 길드 디스코드 채널로만 배포하세요.

## 보안
소규모 지인 서버용이라 길드원의 사용 편의를 우선하는 구조입니다. 지금 막고 있는 것과 남아 있는 한계는 다음과 같습니다.

**막고 있는 것**
- 접속하려면 `/start`로 받은 6자리 일회용 코드가 필요합니다. 코드는 본인에게만 보이는(ephemeral) 메시지로 전달되고, 10분 동안만 유효하며, 한 번 쓰면 무효가 됩니다. 세션 주인이 `/start`를 다시 입력하면 새 코드가 발급되고 이전 코드는 쓸 수 없습니다.
- 실행 파일에는 비밀키가 들어 있지 않습니다(서버 주소만). 서버도 더 이상 공유 비밀키를 쓰지 않습니다. 예전에 공개 Release로 올렸던 실행 파일은 삭제했고, 그 안에 있던 비밀키는 폐기했습니다.
- 틀린 코드가 한 세션에서 100번 쌓이면 그 코드를 무효화하고 `/start`를 실행한 채널에 알립니다(코드 추측이 성공할 확률은 세션당 최대 약 0.01%). 같은 IP에서 60초 안에 5번 실패하면 그 IP를 60초간 거부합니다(메모리에만 저장, 봇을 재시작하면 초기화).
- 세션 하나에 클라이언트 연결은 하나만 허용합니다. 이미 연결이 있으면 새 연결은 코드를 검사하지 않고 close code `4005`로 거부합니다. 응답이 없는 죽은 연결은 정리되어 다시 접속할 수 있습니다.
- 클라이언트가 연결되거나 해제되면 `/start`를 실행한 채널에 알립니다. 메시지 크기는 64KB로 제한합니다.
- 실제 서버 주소는 저장소에 커밋하지 않습니다(`.gitignore`). 커밋 기록에 비밀키가 들어간 적이 없음을 확인했습니다.

**남아 있는 한계**
- 서버 주소가 `ws://`(암호화 없음)라서 접속 코드와 오디오가 네트워크 경로에서 그대로 보일 수 있습니다. 경로상의 도청자가 코드를 본 뒤 먼저 쓰면 세션에 끼어들 수 있습니다. 아직 `wss://`를 적용하지 않았습니다.
- 코드는 6자리라 추측이 불가능하지는 않습니다(위의 한도로 확률만 낮춤). 코드를 아는 사람은 누구든 접속할 수 있으니 코드를 다른 사람에게 보여주지 마세요.
- 세션이 열려 있는지는 인증 없이도 알 수 있습니다(세션이 없으면 `4004`로 거부). 서버 주소는 실행 파일에서 꺼낼 수 있고, 과거 커밋(1708bca, 37b2a33)에도 남아 있습니다.
- `/start` 자체는 길드원 누구나 쓸 수 있습니다. 길드 멤버십을 믿는 구조입니다.
